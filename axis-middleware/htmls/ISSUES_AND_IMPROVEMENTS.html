fix 1. Search-only requests die on the SQL path

POST /query with { search: {...} } passes validation, then compileQuery (axis/src/core/compiler/compiler.ts:37-41) throws CompilationError: Query must contain at least one axis or metric. The user used the wrong endpoint — but the message never says that.

Fix: detect input.search !== undefined in the /query handler → 400: search requests must use POST /search. Explicit, keeps the contract clean.

fix 2. Multi-axis grouping silently drops axes

buildDSL emits a separate <name>_terms agg per axis, but normalizeAggregationRows reads only axes[0]'s buckets. axes: ["department","status"] computes both groupings cluster-side, then discards one client-side.

Fix: nest terms aggs (true multi-level GROUP BY) or reject axes.length > 1 with metrics — silent data loss is the worst option.

fix 3. terms.size reuses the row limit

terms: { field, size: query.limit } conflates rows-to-return with buckets-to-compute. limit: 3 silently truncates to 3 departments.

Fix: separate bucketLimit (e.g. default 1000) from row limit/offset applied post-normalization.

harden 4. No pipeline log

Causes are chained in ExecutionError but the middleware returns a bare 502. The only artifacts are reference/indexed-docs.txt (a snapshot) and e2e console dumps.

Fix: JSON-lines log per request — body → AST → resolved → DSL sent → raw took/total/aggregations → rows → status/duration. Truncate vectors, cap rows, gitignore it (tenant/user data).

harden 5. Number-type split between paths

OS returns native numbers ({ newCount: 6 }); PG returns numeric strings ({ newCount: "6" }). Consumers switching paths break.

Fix: coerce PG numerics to numbers at the executor boundary (JSON-native), plus a cross-path contract test.

harden 6. hasAssignedBuyer / assignedCount unusable

The axis references upeg.requisition_item, absent in po — queries fail at execution, not validation. Create the table, remove the axis/metric, or validate axis SQL against the live schema at startup.

harden 7. Stale-tgz workflow

Every library change needs build → pack → reinstall; forgetting it yields phantom missing-export errors. Prefer npm workspaces so dev can't run stale code.

harden 8. trackTotalHits unset; size defaulted late

Without track_total_hits, total may be approximate while rowCount reports it as exact. And body.size stays undefined until searchDocuments defaults it — default it in the compiler so the DSL is self-contained.

opinion 9. Planner unused by routes

DefaultQueryPlanner encodes routing policy and axis.plan() exposes it, yet app.ts calls query()/searchDocuments() directly. Route through it or delete it — dead policy code rots.

opinion 10. Security asymmetry worth a test

SQL resolves context unconditionally when configured; OS builds term filters only when a context object is passed (axis.ts:208-211). Both fail closed today, but the branches encode the invariant differently. Lock with per-path tests: own rows visible, foreign tenant sees zero, no token → 401.

opinion 11. Keep these docs alive

The old README described a SQL-only system; htmls/ held stale one-off pages. Update README / WORKFLOW / OPENSEARCH with every pipeline change. Suggested work order: #1 → #2 → #5 → #4 → #7.
