1. Connection

OpenSearchAdapter wraps the official client (node / auth / ssl from config). indexPrefix namespaces indices per environment. An injectable client serves tests; the SearchAdapter interface keeps the engine transport-agnostic.

2. Request shape

SearchParams { index, query, size?, from?, sort?, trackTotalHits?, aggs? }
SearchQuery  { bool?, match?, matchAll?, knn? }
BoolQuery    { must?, should?, filter?, mustNot?, minimum_should_match? }
KNNQuery     { field, vector, k, numCandidates?, filter? }

The adapter converts this typed form to the raw OS body and maps took / hits / total / aggregations back to SearchResult.

3. DSL compiler

compileToOpenSearch(resolved, { securityFilters?, queryVector? }) → { index, body }. Index from model.search.index.

buildDSL — filter / agg queries

  • bool combining filters + security terms; size/from from limit/offset; sort from orderBy
  • _source limited to requested axes — narrow payloads
  • One metric agg per metric (value_count / sum / avg / min / max / cardinality); with axes, a <name>_terms agg per axis (terms: { field: "<field>.keyword" }) nesting the metric aggs — the GROUP BY equivalent

buildSearchDSL — search queries

  • fulltext: match per searchable field with minimum_should_match
  • semantic: knn: { embedding: { vector, k } } — vector produced server-side (the compiler never calls the provider)
  • hybrid: both clauses combined; security terms merged into bool.filter so isolation applies before scoring

Text axes filter/sort/group on the .keyword subfield; numerics are coerced to real numbers at index time. debugCompileToOpenSearch(input, model) returns { query, ast, resolved, dsl } for inspection.

4. Execution policy

Metric queries (aggs present) go out with size: 0 — computed cluster-side, zero hits transferred. Document queries send the real size (default 100). Transport failure → ExecutionError("Search execution failed.").

5. Response normalization

  • Metric-only → single row ({ newCount: 6 }), like SELECT COUNT(*) without GROUP BY
  • Axes + metrics → one row per terms bucket ({ department: "Eng", newCount: 2 })
  • metricValue() unwraps { value } from every metric agg type
  • Documents bypass this: rows = hits.map({ ..._source, _id, _score? })

6. Indexing

SELECT source rows → transformer (per model.search: searchable, embeddingInput, embeddingField) → embed → bulk index. created_by/tenant_id travel into the doc for OS-side isolation. Currently department text + embedding vector into purchase-requisitions — the table has no title/description columns.

7. Embeddings

Ollama native (/api/embed) or OpenAI-compatible (POST /embeddings); 384-dim MiniLM here. Used at query time (semantic/hybrid) and index time — nowhere else. Missing provider → ExecutionError naming the fix.

8. Gotchas

  • OS counts are native numbers; SQL returns numeric strings
  • terms.size reuses the row limit — bucket count and row limit conflated
  • trackTotalHits unset → total may be approximate on big indices
  • Multi-axis grouping reads the first axis's buckets only (see issues doc)
  • Search-only requests belong on /search, never /query
